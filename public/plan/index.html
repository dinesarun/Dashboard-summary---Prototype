01

Overview

Today, Dashboard AI generates a summary in a chat-style side panel — it's transient. This release makes that summary persistent and dashboard-native: it lives as a widget, groups insights by module, refreshes on a schedule, and respects per-user permissions.

Three entry points

Any viewer can generate and read a summary. Only edit-permission users can save it as a widget. All three paths converge at "Save summary as new widget".

Entry point A
Summary button on dashboard
Any dashboard viewer
1
User clicks Summary button next to Edit Dashboard
2
Ask AI right-side panel opens, "Summarize dashboard" pre-fired
3
AI generates summary scoped to widgets visible to this user
4
User reads summary in panel
5
"Save summary as new widget" (or "Replace existing summary" if one exists) — visible to edit-permission users only
6
Alert fires → user confirms → widget added at top of dashboard
Entry point B
Widget picker in Edit mode
Edit permission only
1
User opens Edit Dashboard → Add Widget
2
Selects "Dashboard Summary AI" from widget list — disabled if a summary widget already exists on this dashboard
3
Ask AI right-side panel opens, "Summarize dashboard" pre-fired
4
AI generates summary scoped to this user's visible widgets
5
User clicks "Save summary as new widget"
6
Alert fires → user confirms → widget added at top of dashboard
Entry point C
Ask AI panel — manual
Any dashboard viewer
1
User clicks Ask AI button (global)
2
Types or selects "Summarize dashboard"
3
User selects dashboard + time range from dropdown
4
AI generates summary scoped to user's visible widgets for that dashboard + range
5
"Save summary as new widget" (or "Replace existing") — visible to edit-permission users only
6
Widget lands on the selected dashboard. Toast: "Summary widget added to Dashboard X. [Go there]"
Permission-scope alert (all 3 entry points): "This summary reflects your current data access. Some users may not see all modules this summary references."  — Exact text to confirm with Pooja.

Widget anatomy

Seven states the saved widget needs to render. All variants share the same shell: header (title + refresh + overflow menu), a "last updated" timestamp, and module sections with severity-cued bullets. Settings live inside the ⋮ overflow menu to match existing widget chrome — refresh stays in the header because it's the primary action.

Permission matrix

Widget follows dashboard permissions. Viewers can read and generate; editors can save, configure, and consent to updates.

Lower permission view behaviorTo confirm with Pooja
Lower-permission detection — why this matters: a viewer for whom Meta Ads (or any other module) is not enabled could otherwise see summary content about a module they can't access. They'd never be able to see the underlying widget or open that module — yet the summary would leak insights about it. System checks on render: if any widget on the dashboard belongs to a module not activated for this user → flag the dashboard as "lower permission" for them. Two options open: (A) hide the widget entirely so the user falls back to generating their own via Ask AI, or (B) show the locked state from Section 3 / D.
